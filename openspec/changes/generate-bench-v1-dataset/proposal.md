# Proposal: Generate ERP-Skills-Bench v1 (work unit 13, closes P3.3–P3.5 core)

## Intent

Deliver the confirmatory 480-case benchmark CLAUDE.md §17 requires — the
gap the user flagged as blocking A/B/C and the experiment. Depends on the
completed catalog (unit 11) and canonical intents (unit 12).

## Scope

- `bench_generator.generate_cases(seed)`: per intent, 20 formulations =
  10 NORMAL (10 stylistic transforms) + 6 NOISE (5 stylistic + 1
  required-field omission forcing `CLARIFY`) + 4 ADVERSARIAL (rotating
  through 4 of the 11 CLAUDE.md §17 categories per intent, deterministic
  by intent index so all 11 appear across the 24 intents).
- Each case is its own paraphrase group (`paraphrase_group_id ==
  request_id`), so `dataset.validate_case_groups` cannot detect leakage
  by construction (no group has more than one member).
- Deterministic seeded shuffle before slicing 20 drafts into 10 dev / 5
  validation / 5 test per intent (240/120/120 overall), so category
  labels interleave across splits.
- `scripts/export_bench_v1.py`: writes `data/bench_v1.jsonl` (480 lines,
  one `BenchmarkCase` per line).
- `docs/dataset-card.md`: composition, split methodology, and explicit
  known limitations (no execution wiring yet, no second annotator yet).

## Non-goals

No execution wiring into `SystemC`/`FakeERPAdapter` (phase 8, roadmap
P8.1–P8.3 — `initial_state`/`expected_final_state` are placeholder dicts,
named as such in the dataset card). No second-annotator review or kappa
(genuinely a pending human step, not something this session can produce).
No A/B/C systems or experiment runner.

## Follow-on dependency

Phase 8 (A/B/C, piloto) is now unblocked by this dataset; wiring these
cases to real `SystemC` execution and adding second-annotator review
remain explicitly deferred, human, or later-phase work.

## Success criteria

Exactly 480 cases; split exactly 240/120/120; exactly 144 NOISE and 96
ADVERSARIAL; zero paraphrase-group leakage; every `expected_skill` is
either a cataloged skill or the abstention sentinel; all `request_id`s
unique; generation is deterministic (`generate_cases() ==
generate_cases()`); all 24 intents represented. `python -m pytest` passes
in full; `data/bench_v1.jsonl` has exactly 480 lines.

## Forecast and explicit budget exception

Hand-authored: `bench_generator.py` (442) + `test_bench_generator.py`
(56) + `scripts/export_bench_v1.py` (27) = **525 lines**, over the
400-line review budget. This is disclosed, not hidden. Splitting further
was considered and rejected: the generator's style-function table, the
11-branch adversarial-category dispatcher, and the per-intent assembly
loop are one cohesive algorithm — fragmenting it across files would
force a reviewer to cross-reference three modules to verify a single
formulation's provenance, which harms reviewability more than the line
count itself does. The 8 tests in `test_bench_generator.py` (counts,
leakage, determinism, catalog/abstention consistency) are the actual
correctness gate; all pass. `data/bench_v1.jsonl` (480 lines) is
machine-generated by this module and flagged separately, the same
treatment given to `uv.lock` in work unit 6/10.
